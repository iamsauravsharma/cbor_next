1//! Converting between Rust values and data items with serde.
2//!
3//! [`to_data_item`] and [`to_vec`] write any value which implements
4//! `Serialize`, and [`from_data_item`] and [`from_slice`] read one which
5//! implements `Deserialize`. A [`DataItem`](crate::DataItem) implements both
6//! traits itself, so it can also be written to or read from another format.
7//!
8//! ```rust
9//! use cbor_next::serde::{from_slice, to_vec};
10//! use serde::{Deserialize, Serialize};
11//!
12//! #[derive(Serialize, Deserialize, Debug, PartialEq)]
13//! struct Point {
14//!     x: i32,
15//!     y: i32,
16//! }
17//!
18//! let bytes = to_vec(&Point { x: 1, y: -2 }).unwrap();
19//! // a map of two entries: {"x": 1, "y": -2}
20//! assert_eq!(bytes, [0xa2, 0x61, 0x78, 0x01, 0x61, 0x79, 0x21]);
21//! assert_eq!(from_slice::<Point>(&bytes).unwrap(), Point { x: 1, y: -2 });
22//! ```
23//!
24//! # Data serde has no counterpart for
25//! `CBOR` holds a few things the serde data model does not. Each one has a
26//! type which carries it through serde unchanged, and which falls back to a
27//! plain structure through any other format:
28//! - a tag is written and read with [`Tagged`], or with [`TaggedWith`] when the
29//!   tag number is fixed by the protocol; a [`Tag`](crate::Tag) implements the
30//!   traits the same way
31//! - `undefined` is written and read with [`Undefined`]
32//! - any other simple value is written and read with [`Simple`](crate::Simple)
33//! - an integer outside the range of `CBOR`, -2^64 to 2^64 - 1, is written as a
34//!   bignum, tag 2 or 3 of RFC 8949 section 3.4.3, and a bignum is read as an
35//!   `i128` or `u128`
36//! - a map key may be any value, as in both data models
37//!
38//! Anything which falls outside of that is rejected with
39//! [`Error::Unsupported`], never altered to fit: a tag which nothing asked
40//! for, `undefined` or a simple value in place of another type, a bignum
41//! wider than 128 bits and a map which uses the same key twice, which RFC
42//! 8949 section 5.6 calls invalid.
43//!
44//! Indefinite length strings, arrays and maps are accepted when reading, their
45//! chunks joined, and values are always written with a definite length, the
46//! preferred serialization once the length is known. An enum is written the
47//! way serde does by default: a unit variant as its name and any other
48//! variant as a map of one entry from its name to its content.
